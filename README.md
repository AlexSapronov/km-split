# Разделение КМ — отдельный складской MVP

Самостоятельное приложение для ПК: FastAPI + SQLite + обычный JavaScript.
Не использует базу и настройки `gis-trueapi`. Сервис `km-split.service`,
каталог `/opt/km-split`, порт **8010** (8001 уже занят).

## Что сделано

1. Скан исходного DataMatrix: проверка формата/GTIN, исправление русской раскладки,
   сохранение полного криптохвоста и управляющих разделителей.
2. True API: владелец, статус «В обороте», `quantityInPack`, PN из поля `model`
   (при необходимости из карточки товара). Без достоверного PN и количества
   эмиссия не начинается. Исходный DM может не содержать количество — как
   в предоставленном образце этикетки.
3. Ввод целого отделяемого количества от 1 до доступного остатка минус 1.
   Незавершённые разделения резервируют количество в SQLite транзакционно.
4. Подготовка и подпись заказа: `REAPPLY`, `OPERATOR`, `quantity: 1`,
   `paymentType: 1`, на тот же GTIN и от владельца исходного КМ.
5. Получение нового КМ после готовности заказа. Количество добавляется как AI 30.
6. PDF **58 × 40 мм**: DataMatrix слева, КИ под ним, логотип ЧЗ справа,
   PN и количество. Компоновка по образцу склада. PDF хранится на сервере;
   повторная загрузка печатает тот же КМ и не вызывает эмиссию.
7. Пакетная подготовка отчётов по выбранным нанесённым этикеткам. Группировка
   по организациям. `DIVISIONMARK`: полный новый КМ с AI 30 + ASCII 30 + полный
   исходный КМ. Отправка по кнопке сотрудника в середине/конце дня.
8. Статус отчёта + квитанция. Только подтверждённый полный успех переносит
   операции в историю со статусом «Успешно нанесено». Частичный или неизвестный
   результат остаётся в рабочем списке. Квитанция сохраняется на сервере.

**Режим по умолчанию — demo.** Он не обращается в ЧЗ, не эмитирует настоящие КМ,
не использует ЭЦП. На PDF явно указано «DEMO — НЕ ДЛЯ ОБОРОТА».
Live-клиент реализован, но первая реальная операция и подпись аппаратной ЭЦП
требуют проверки на рабочем ПК с вашими доступами. Эти проверки не заменяются
локальными автотестами.

## Быстрый локальный запуск

Python 3.12, Linux/Windows. На Linux нужен шрифт DejaVu Sans; в Ubuntu:

```bash
sudo apt-get install python3-venv fonts-dejavu-core
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

В `.env` задайте длинный `SPLIT_PASSWORD`, затем:

```bash
.venv/bin/python -m uvicorn main:create_app --factory --host 127.0.0.1 --port 8010
```

Откройте http://127.0.0.1:8010. Логин `warehouse`, пароль из `.env`.
Кнопка «Попробовать на демо-коде» проводит весь процесс без реального ЧЗ.

## Установка на VPS рядом с существующим приложением

Не останавливайте `gis-trueapi.service`. Убедитесь, что 8010 свободен:

```bash
sudo ss -ltnp 'sport = :8010'
```

Если вывод содержит слушающий процесс, выберите другой порт в `deploy/km-split.service`
и в SSH-туннеле. Для `8010` пустой вывод означает отсутствие слушателя в момент проверки.

Репозиторий: https://github.com/AlexSapronov/km-split.
Разместите исходники отдельно от существующего приложения:

```bash
sudo git clone https://github.com/AlexSapronov/km-split.git /opt/km-split
```

Затем:

```bash
sudo apt-get update
sudo apt-get install -y python3-venv fonts-dejavu-core curl
sudo useradd --system --home-dir /opt/km-split --shell /usr/sbin/nologin kmsplit
sudo mkdir -p /opt/km-split/data
sudo chown -R kmsplit:kmsplit /opt/km-split
sudo -u kmsplit python3 -m venv /opt/km-split/.venv
sudo -u kmsplit /opt/km-split/.venv/bin/python -m pip install -r /opt/km-split/requirements.txt
sudo -u kmsplit cp /opt/km-split/.env.example /opt/km-split/.env
sudo chmod 600 /opt/km-split/.env
sudo chmod 700 /opt/km-split/data
sudo nano /opt/km-split/.env
```

В `.env` оставьте `SPLIT_MODE=demo`, задайте пароль. В systemd фиксирован
`WorkingDirectory=/opt/km-split`; относительный `SPLIT_DATA=data` разрешается от него.

```bash
sudo cp /opt/km-split/deploy/km-split.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now km-split.service
sudo systemctl status km-split.service --no-pager -l
curl --fail http://127.0.0.1:8010/health
```

На Windows-ПК откройте PowerShell и подключите туннель:

```powershell
ssh -L 8010:127.0.0.1:8010 smartuser@АДРЕС_VPS
```

Пока SSH открыт, приложение доступно на ПК по http://127.0.0.1:8010.
Сам сервис слушает только loopback; открывать 8010 в firewall для этого не требуется.
Для постоянного общего доступа используйте отдельный HTTPS virtual host reverse proxy
на `127.0.0.1:8010`. Передача Basic-пароля по открытому HTTP через Интернет не предусмотрена.

## Подключение ЧЗ и ЭЦП

### Организации

Сначала проверьте демонстрационный процесс. Для live используйте **другой каталог
данных**, например `/opt/km-split/data/live`, а не существующую demo-базу:

```bash
sudo -u kmsplit mkdir -p /opt/km-split/data/live
sudo -u kmsplit cp /opt/km-split/organizations.example.json /opt/km-split/data/live/organizations.json
sudo nano /opt/km-split/data/live/organizations.json
```

Для каждой организации нужны:

- `inn`, `name`;
- `oms_id` — идентификатор СУЗ;
- `oms_connection` — идентификатор зарегистрированного подключения интеграционного решения;
- `true_api_url`, `oms_url` — согласованная пара адресов среды (боевой либо тестовой);
- `template_id`: 36 (91/92) либо 37 (93);
- опционально `producer_inn` для заказа по исходному глобальному GTIN, когда СУЗ
  требует ИНН владельца карточки. Это не подмена владельца исходного КМ.

Не копируйте реальные реквизиты/токены в публичный репозиторий. Конфиг с ними хранится
только в `data/`, исключённом из Git.

В `.env` измените:

```dotenv
SPLIT_MODE=live
SPLIT_DATA=/opt/km-split/data/live
```

Перезапустите **только** `km-split.service`.
Для каждой организации откройте «Доступ к ЧЗ», выполните авторизацию ГИС МТ и СУЗ
по отдельности. Единый токен True API не заменяет токен СУЗ с `omsConnection`.

### Подпись в браузере

На ПК нужны КриптоПро CSP, ЭЦП Browser plug-in, расширение и действующий
сертификат с закрытым ключом на подключённом токене. Добавьте адрес приложения
в доверенные для плагина. Полномочия сотрудника/МЧД проверяются ЧЗ.

На сервере установите официальный JS-мост КриптоПро:

```bash
sudo -u kmsplit bash /opt/km-split/scripts/install-crypto-bridge.sh
```

Он скачивается с официального домена, хранится в `static/vendor/` и не включается
в исходники. Кнопка «Загрузить» покажет действующие сертификаты с закрытым ключом.
Выберите сертификат, нажмите «Подписать и отправить». PIN вводится в окне
криптопровайдера. Приложение не получает PIN и закрытый ключ.

- Авторизация: **присоединённая** подпись challenge (`detached=false`).
- Заказ и отчёт: **отсоединённая** CMS/CAdES-BES (`detached=true`) в `X-Signature`.
- Подписываются точные UTF-8 байты, переданные через Base64. Сервер отправляет
  сохранённое тело без повторной сериализации.

### Подпись файлом

Если браузерный плагин недоступен, в окне подписи раскройте соответствующий блок:
скачайте `sign-....json` и `sign-job.ps1`, запустите в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sign-job.ps1 -JobFile .\sign-ИДЕНТИФИКАТОР.json
```

Скрипт показывает организацию, действие, SHA-256 и подписываемое содержимое.
Выберите сертификат и подтвердите `YES`. Загрузите созданный `.sig` в окно
приложения и нажмите «Подписать и отправить». Скрипт сам не отправляет документы.
Файл задания содержит полные КМ; храните его как рабочий документ, не в публичном Git.

## Рабочий процесс сотрудника

1. Сканируйте исходный КМ и проверьте организацию, PN, доступный остаток.
2. Введите отделяемое количество. После создания подпишите заказ.
3. Нажмите «Получить КМ». Если СУЗ ещё готовит его, повторите **проверку готовности** позже.
4. Скачайте PDF. Печать: бумага **58 × 40 мм**, масштаб **100%**, без «вписать в страницу».
   Повторная печать — через тот же PDF. Убедитесь, что новая этикетка читается сканером.
5. Наклейте этикетку на отделённый товар.
6. В середине/конце дня отметьте операции, нажмите «Подготовить отчёт», подтвердите
   фактическое нанесение и подпишите отчёт каждой организации.
7. Нажмите «Проверить результат». После квитанции об успехе операции уйдут в историю.

**Скачивание PDF не подтверждает нанесение. Отправка отчёта не подтверждает его обработку.**
Исходную наклейку после частичного разделения не перепечатываем: актуальный остаток
берём из ЧЗ. На старой бумажной этикетке может остаться прежнее количество.

## Сбои и ограничения MVP

- Idempotency по UUID запроса защищает создание от повторного нажатия. Транзакции
  защищают резервирование количества. Повторный POST подписанного задания не создаёт
  второй внешний запрос.
- Timeout при эмиссии/отчёте, потеря ответа и перезапуск между отправкой и сохранением
  результата **не приводят к автоматической повторной отправке**. Операция остаётся
  видимой и продолжает резервировать количество. Проверьте ЛК.
- Для неизвестного результата **заказа** можно указать ID из ЛК после ручной сверки
  `productionOrderId` с ID операции и GTIN. Проверяется доступность заказа для GTIN.
  Это ручное подтверждение, а не автоматическое доказательство соответствия заказа.
- Если потерян ответ `GET /codes`, выдача может уже быть списана из буфера.
  Повтор не выполняется. Восстановление через блоки/квитанции СУЗ в UI MVP не включено.
- Неизвестный/частичный результат **отчёта** требует ручного разбора квитанции.
  Автоматической повторной отправки или освобождения резерва нет.
- Изменение исходного КМ через другой сервис или ЛК блокирует последующее разделение
  до разбора. Приложение не может резервировать количество в чужих системах.
- После успешного отчёта новое разделение ждёт, пока True API покажет ожидаемый
  остаток. В резерве не происходит двойного списания одного успешного отчёта.
- В этой версии только целые штуки, радиоэлектроника, исходный статус `INTRODUCED`.
  Вес, метры, литры, ТСД, автопечать, изменения формата этикетки, разграничение ролей
  и автоматический фоновый опрос не включены.
- Условие полной успешной квитанции консервативное: `reportStatus=SUCCESS`,
  соответствующий `sourceDocId`, все полученные квитанции `state=SUCCESS`, `code=0`.
  На пилоте нужно сопоставить с реальной квитанцией вашей группы; незнакомый формат
  не закрывает операции автоматически.
- `quantityInPack` используется как текущий количественный источник True API,
  как в существующем приложении. Фактическое изменение этого поля после разделения
  надо проверить на первой реальной операции; при несовпадении последующие действия
  блокируются, а не продолжают работу по предположению.

## Данные и резервные копии

`SPLIT_DATA`: `split.sqlite3` (операции, точные тела заданий, токены, журнал),
`labels/` (PDF), `receipts/` (квитанции), `organizations.json` (организации).
Каталог 0700, база и создаваемые файлы 0600. Не публикуйте его в Git и не
раздавайте как статическую папку.

```bash
sudo -u kmsplit bash /opt/km-split/scripts/backup.sh
sudo journalctl -u km-split.service -n 80 --no-pager
```

Резервная копия создаётся SQLite online-backup с учётом WAL и включает этикетки,
квитанции и конфиг организаций. Архив содержит токены и КМ; храните его закрыто.
Для строгой согласованности базы и файлов во время восстановления используйте
копию, сделанную при остановленном `km-split.service`. `.env` сохраните отдельно.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
node --check static/app.js
python -m playwright install chromium
python tests/browser_smoke.py
```

Для теста PDF нужны `poppler-utils`. Проверяется размер страницы, читаемость DM
при 203 dpi, GS1/FNC1 (`]d2`) и точное совпадение декодированных байтов, включая
криптохвост и AI 30. Тесты API используют имитации HTTP, без реальной эмиссии.

## Документация, на которую опирается интеграция

- § 4.4.2 и 4.4.4 — готовность буфера и выдача кода;
- § 4.4.11.1.15, стр. 260–265 — AI 30 и DIVISIONMARK;
- § 4.4.13, 4.4.18 — статус и квитанция;
- § 9.3.2 — авторизация СУЗ с omsConnection, присоединённая подпись;
- § 2.3.1 — отсоединённая CMS-подпись запросов.

True API: пути и форма ответов сверены с клиентом `AlexSapronov/gis-trueapi`;
его код и рабочая база в этот репозиторий не включены.

и https://docs.cryptopro.ru/cades/plugin/content-encoding.

## Публичный репозиторий

Исходники не включают реальные КМ из образца, PDF API, `.env`, runtime-конфиг
или скачанный JS-мост КриптоПро. Логотип ЧЗ извлечён из предоставленного образца
этикетки; права на знак принадлежат его правообладателю.
Исходники опубликованы отдельно: https://github.com/AlexSapronov/km-split.
Обновляйте только этот репозиторий и `km-split.service`; существующий
`gis-trueapi` продолжает работать независимо.
